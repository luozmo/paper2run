# 04: 复杂内容可靠呈现与最终验收

**What to build:** 学生能够阅读包含中文、长链接、多行命令、特殊字符和长表格的完整报告文档，两种格式内容一致，Word 页面清晰可读；调用方能够依照已有接口集成经过整体验收的报告生成模块。

**Blocked by:** 03 — 证据编号与来源追溯。

**Status:** ready-for-agent

- [ ] 中文、特殊字符、技术名称、路径、原文引用和命令在两种格式中正确表达；格式处理不丢失或改变原始内容含义。
- [ ] 长链接和多行命令可读，内容不会串入相邻表格单元格或误变成报告结构。
- [ ] 长表格能够合理换行和跨页，在 A4 页面中没有明显截断、重叠或横向溢出；保持已确认的标题、表格及等宽命令样式。
- [ ] 使用完整报告及复杂内容样例，将实际生成的 Word 渲染为页面并查看全部最终页面，发现问题后修正并复查；保留实际检查证据。
- [ ] 自动核对两种格式的事实、参数、章节和证据引用一致性，不将不同格式的原始字节相等作为要求。
- [ ] 重验完整数据、最小数据、部分缺失、重复证据、两处依赖冲突和全部参数对照状态。
- [ ] 重验任一同名目标存在、输出位置异常和某种格式生成失败等情况，确认原有文件不变、本次不完整输出被清理。
- [ ] 测试主要经由现有 ReportRenderer.render 入口验证外部行为，使用 fixture 和受控失败模拟，不为测试新增业务接口或依赖真实外部服务。
- [ ] 运行完整项目测试并保存真实结果，不能将现有 FakeRenderer 的接口组合测试视为真实导出已通过验收。
- [ ] 提供简短的模块使用说明，解释如何提供分析数据、指定输出目录、取得两份文件和处理失败，便于集成负责人接入；不修改共享命令行和流水线。
- [ ] 完成的功能符合已确认规格，报告生成模块、模块说明和测试不扩大到其他成员负责的业务范围；运行产物和凭据不进入提交。

此工单同时完成整体验收，因此等待内容展示和证据追溯全部完成后执行。页面渲染仅用于质量检查，不增加独立 PDF 导出功能。
