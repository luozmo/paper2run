# 01: 基础双格式导出与文件保护

**What to build:** 调用方提供只有论文基本信息的分析数据和输出目录，即可通过现有报告生成接口获得可阅读的 Markdown、Word 报告文档。缺少仓库和分析结果时保留主要章节并说明缺失；输出失败时保护原有文件并避免留下本次不完整报告。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 提供符合现有 ReportRenderer 协议的实际实现，接收 PaperReport 和输出目录；不修改共享接口或模型。
- [ ] 用最小有效分析数据生成 report.md 与 report.docx，两份文件均可重新打开，论文基本信息及已有内容一致。
- [ ] 保留概览、论文基本信息、代码仓库及官方状态、依赖与环境、运行入口与命令、论文实验条件、参数对照、缺失项与警告、证据等章节；空章节具体说明未提供的信息。
- [ ] 没有仓库、仓库检查或参数对照数据时仍成功生成报告；不把信息缺失描述为没有依赖或参数一致。
- [ ] 使用中文技术报告风格，Word 采用 A4 和清晰标题层级，不增加封面或目录页。
- [ ] 输出目录不存在时创建；输出位置不可写或不是目录时明确失败。
- [ ] 任一目标同名文件已存在时明确报错，不覆盖该文件，也不产生另一份半成品；目录中原有其他文件保持不变。
- [ ] 只有两种格式都成功时才返回两个实际文件的路径；任一格式失败时明确报错，清理本次不完整输出并保护原有文件。
- [ ] 从公开导出入口测试最小有效输入、可选字段缺失、目录创建、同名文件保护、受控写入失败和清理行为；核对文档内容，不仅检查文件存在。
- [ ] 测试使用临时目录和构造数据，不依赖 GitHub、DSH 或 API Key；模块改动符合现有协作边界，现有项目测试保持通过。

本工单建立可运行的最小导出流程；完整分析字段展示、证据追溯和复杂内容排版由后续工单逐步补齐。这里只实现报告文档生成，不接入实际命令行或修改共享流水线。
