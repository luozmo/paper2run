# Markdown、Word 报告文档导出

## Problem Statement

准备复现计算机论文的学生需要将论文、代码仓库、依赖和实验条件放在一起阅读，并追溯对应证据。目前 Paper2Run 已有结构化分析数据和报告生成接口，但缺少可阅读、可分享的 Markdown 与 Word 报告文档。直接阅读分析数据既不方便核对实验条件，也不利于向小组展示缺失和不一致的信息。

## Solution

接收上游提供的分析数据，一次生成内容一致的 Markdown 和 Word 报告文档。报告面向读过论文、准备复现的学生，以中文概览、分节表格、参数对照和可追溯证据帮助读者查找代码、准备环境和确认待补充的信息。

报告生成只呈现已有分析数据，不执行检索、模型调用或新的事实判断。信息不全时照常生成报告并具体说明；文件无法完整生成时明确失败并保护已有文件。

## User Stories

1. As a 准备复现论文的学生, I want a 简短的报告概览, so that 我能快速了解仓库状态、已提供的信息和待确认项。
2. As a 准备复现论文的学生, I want a 论文基本信息章节, so that 我能确认报告对应的标题、作者及已有出版信息。
3. As a 准备复现论文的学生, I want a 候选仓库和选中仓库的展示, so that 我能找到相关代码并区分候选与最终选择。
4. As a 准备复现论文的学生, I want a 中文仓库官方状态及其已有说明, so that 我能理解上游对仓库来源的判断。
5. As a 准备复现论文的学生, I want a 依赖与环境章节, so that 我能据已有信息准备复现环境。
6. As a 准备复现论文的学生, I want a 分别标明来源的汇总依赖和仓库检查依赖, so that 我能识别两处数据的区别。
7. As a 准备复现论文的学生, I want a 保留同名依赖不同版本的展示, so that 我能看到分歧并自行核实。
8. As a 准备复现论文的学生, I want a 运行入口和命令章节, so that 我能找到上游识别出的程序启动方式。
9. As a 准备复现论文的学生, I want a 保持原文的多行命令和路径, so that 我能准确阅读技术内容。
10. As a 准备复现论文的学生, I want a 论文实验条件章节, so that 我能查看数据集、模型、框架、硬件和训练评测设置等已有信息。
11. As a 准备复现论文的学生, I want a 分列论文值与仓库值的参数对照, so that 我能直接核对具体差异。
12. As a 准备复现论文的学生, I want a 中文化的上游对照状态, so that 我能理解一致、不一致、单侧缺失和无法确认等情况。
13. As a 准备复现论文的学生, I want a 缺失项与警告章节, so that 我能知道复现前还需要补充什么。
14. As a 准备复现论文的学生, I want a 没找到仓库时仍可阅读的报告, so that 我仍能利用论文抽取结果。
15. As a 准备复现论文的学生, I want a 明确说明尚未提供的模块结果, so that 我不会把没有数据理解成没有依赖或参数一致。
16. As a 准备复现论文的学生, I want a 正文中的证据编号, so that 我能从结论追溯到对应材料。
17. As a 准备复现论文的学生, I want a 集中展示的证据来源、页码或文件位置、引用和已有链接, so that 我能核对上游依据。
18. As a 准备复现论文的学生, I want a 重复证据复用同一编号的报告, so that 我能清楚识别多处内容是否依据同一材料。
19. As a 准备复现论文的学生, I want a 明确标注缺少证据的内容, so that 我能区分已有依据与尚未提供依据的信息。
20. As a 分享报告的小组成员, I want a Markdown 报告文档, so that 我能在支持 Markdown 的工具中阅读和分享结果。
21. As a 分享报告的小组成员, I want a Word 报告文档, so that 我能打开、编辑和提交报告材料。
22. As a 分享报告的小组成员, I want a 两种格式事实、章节和证据一致的报告, so that 分享不同格式时不会造成信息分歧。
23. As a 阅读 Word 的学生, I want a 简洁的 A4 技术报告版式, so that 我能通过标题层级、表格和命令文本快速查阅。
24. As a 阅读报告的学生, I want a 正确呈现中文、长链接、特殊字符和长表格的文档, so that 我不会因排版或转义问题误读内容。
25. As a 集成负责人, I want a 符合现有报告生成接口的模块, so that 我能将导出功能接入流水线。
26. As a 集成负责人, I want a 自动创建不存在的输出目录的导出功能, so that 我能直接指定新的结果位置。
27. As a 保存报告的小组成员, I want a 保护已有同名报告的导出功能, so that 我不会因重复运行丢失已有材料。
28. As a 集成负责人, I want a 仅在两种格式都成功时返回的路径列表, so that 我能把返回成功理解为两份报告均已生成。
29. As a 保存报告的小组成员, I want a 失败时清理本次不完整输出的导出功能, so that 我不会把半成品当作完成的报告。
30. As a 维护报告模块的小组成员, I want a 不依赖 API Key 的自动测试和 Word 页面检查, so that 我能独立验证内容、错误行为和阅读效果。

## Implementation Decisions

- 在报告生成模块内完成导出实现、模块说明及必要测试，遵守当前模块边界。共享模型、配置、接口、依赖、命令行和流水线由集成负责人维护；本规格不要求修改它们。
- 采用现有 ReportRenderer 的 render 接口，接收 PaperReport 和输出目录，返回生成文件的路径列表。具体实现应能作为该协议的实现被集成负责人使用；不新增跨模块服务接口。
- 用户已确认“分析数据”和“报告文档”的术语区别。正文使用这些术语，避免将内部数据误称为已导出的文档。
- 报告为简短概览，随后为论文基本信息、代码仓库及官方状态、依赖与环境、运行入口与命令、论文实验条件、论文与仓库参数对照、缺失项与警告，末尾集中列出证据。
- 只使用传入的分析数据；不调用模型、联网搜索、运行论文代码或推导新的实验设置。概览同样只概括已提供的状态和信息。
- Markdown 与 Word 使用相同的事实、章节、证据编号与引用依据；具体排版适配各自格式。文本内容中的特殊字符按目标格式正确表达，不能改变技术值、路径或命令含义。
- 正文使用中文技术报告风格，状态标签中文化，技术名称、命令和路径保持原文。Word 使用 A4、清晰标题层级、表格和等宽命令文本，不增加封面或目录页。
- 主要章节在缺失数据时仍保留，并准确说明未提供的内容。空依赖列表不转换为“没有依赖”；不存在仓库检查结果不转换为已经完成检查。
- 论文参数与仓库参数分列，沿用上游对照状态，不重判一致性。仓库可用状态、官方状态和选中仓库也按上游字段呈现，不因一个字段存在而补全另一个字段。
- 汇总依赖与仓库检查依赖分别展示、保留已有证据；同名依赖版本有差异时不擅自选择或合并。不将汇总依赖擅自标成论文来源。
- 正文事实关联已有证据编号，末尾呈现来源、已有页码或文件位置、原文引用及链接。相同证据复用编号；不存在的引用、位置和链接不得补造，缺少证据时明确标注。模型中的证据位置是上游提供的数据，本模块不执行事实核验。
- 输出文件固定命名为 report.md 和 report.docx。指定目录不存在时创建；任一目标已存在时明确报错，不覆盖，调用方应使用新目录。
- 两种格式均生成成功才返回两个实际文件的路径。任一生成失败则整次失败、明确报错，并清理本次产生的不完整输出；不得删除或改写原有文件。此规则要求处理正常执行中可捕获的失败，不承诺机器断电等情况下的跨文件事务。
- 上游信息不足是可展示的内容状态，与输出不可写、文件生成失败等导出错误分开处理。沿用现有 PaperReport 的可选字段，不要求更改模型。
- 沿用项目已声明的 Word 文档依赖。内部组织和字体等可逆细节由实现时依据已确认版式和验收标准选择；不因此增加用户需求。

## Testing Decisions

- 主要测试入口采用现有 ReportRenderer.render：向其传入构造好的分析数据和临时目录，检查返回路径、实际生成的两份报告内容、错误结果和目录中保留的文件。这是现有流程调用的最高报告模块边界，用户已在 Q1、Q3、Q11 确认该输入输出范围及验收方式，不新增为测试而存在的业务接口。
- 测试只验证外部可观察行为，不绑定私有方法、内部类结构或某一段格式拼接代码。Word 的语义内容可通过重新打开文档核对；Markdown 核对实际文本、章节、表格与证据引用。不能仅凭文件存在判定导出正确，也不要求两种格式的原始字节相同。
- 借鉴现有共享模型契约测试的构造、序列化验证方式，以及现有流水线测试通过 fake 服务隔离外部调用的方式。现有 FakeRenderer 只证明接口组合，不证明真实文档生成；需要补足实际报告生成行为的测试。
- 完整数据样例覆盖固定章节、两处依赖、入口命令、各类实验条件、各类对照状态、缺失项和警告。核对中文状态、原始技术值和两种格式的事实一致性。
- 缺失样例包括只有论文基本信息、没有找到仓库、没有仓库检查或对照结果、空集合、可选字段为空和事实缺少证据。保持章节可读，并避免将缺失误写成否定结论。
- 证据样例包括重复证据、论文页码、仓库文件位置、带链接或缺少可选属性的证据。核对编号复用、引用对应和未提供证据的标记。
- 冲突样例覆盖同名依赖版本不同和参数不一致，确认来源、双方数值、上游状态与说明得到保留，而非被自动纠正或合并。
- 复杂内容样例覆盖中文、长链接、多行命令、Markdown 特殊字符和较长表格，确认内容不会因转义或布局而丢失、变形或串入相邻字段。
- 异常样例覆盖任一目标同名文件已存在、输出位置不可写、输出位置为非目录和一种格式写入失败。验证清晰失败、原有文件不变、本次不完整输出得到清理；失败模拟应可靠且不依赖当前操作系统恰好采用某种权限行为。
- 使用 fixture、临时目录和必要的受控失败模拟，不依赖真实 GitHub、DSH 或 API Key。生产导出模块不为测试额外暴露跨模块接口。
- 实现后运行完整项目测试。将实际生成的 Word 渲染为页面，检查最终样例的全部页面，确认中文可读，没有明显截断、重叠或表格溢出。页面检查补充自动内容测试，不能用成功退出代替。
- 上述均为待执行的验收标准；本次规格编写没有运行新实现的测试或进行页面验收。

## Out of Scope

- GitHub 仓库搜索、获取、候选排序及官方状态判断。
- 依赖解析、运行命令推断、论文抽取、实验参数对照或事实真伪核验。
- 新的大模型调用、API Key 配置、论文复现执行或训练。
- 修改共享模型与接口、增加项目级依赖、正式接入命令行和流水线。
- 网页或桌面界面、中期 PPT 制作、封面、自动目录和独立 PDF 导出功能。
- 自动覆盖已有报告、多论文批量导出、用户自定义模板或额外输出格式。

- 需求复查未发现需要重开采访的阻塞问题。两处依赖字段按已确认的来源区分策略处理，测试集中在现有报告生成接口；已有高层接口足够，无需新增测试专用业务边界。
- 用户随后明确授权 implement-spec，四张本地工单已按顺序完成，完整测试和 Word 页面验收已执行；实际依据见模块验收记录。
- 用户已明确选择保留本地规格和独立本地工单，不发布远程 Issue、不执行全仓 setup。本次任务无需额外配置 issue tracker 或远程标签。工单按 01 → 02 → 03 → 04 的顺序完成并标记 done。
